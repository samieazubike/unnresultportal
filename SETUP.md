# Setup Guide

Result Processing System with Data Visualization — Department of Computer Science, University of Nigeria, Nsukka.

This guide takes you from a fresh clone to a seeded, running portal with tests passing. For what the system *is* and why it is built this way, read [README.md](README.md) — that file is the authoritative implementation spec, this one is purely operational.

---

## 1. Prerequisites

| Requirement | Version | Notes |
|---|---|---|
| PHP | **8.3+** | `composer.json` requires `^8.3`. CI runs 8.5. |
| PostgreSQL | **16** | Not optional — see §4. |
| Node.js | **22** | The version CI builds against. |
| Composer | 2.x | |
| npm | bundled with Node | |

### PHP extensions

Composer will not warn you about most of these, so check them first with `php -m`:

| Extension | Needed for |
|---|---|
| `pdo_pgsql` | The database. **The most common missing one** — it is not a declared Composer requirement, so `composer install` succeeds without it and the app then fails at the first query. |
| `gd`, `zip`, `xml`, `simplexml`, `iconv` | PhpSpreadsheet — the Excel score upload |
| `dom`, `mbstring` | DomPDF — transcript generation |
| `ctype`, `fileinfo`, `filter`, `hash`, `json`, `openssl`, `session`, `tokenizer` | Laravel itself |

### Optional

- **Ollama** — only if you want LLM-phrased recommendations. The app works fully without it. See §7.
- **Swoole** or **RoadRunner** — only if you run the app under Octane. Not needed for normal development.

## 2. Install

```bash
git clone <repo-url> && cd unnresultportal

composer install
cp .env.example .env
php artisan key:generate

createdb unnresultportal          # or: psql -c 'CREATE DATABASE unnresultportal;'
php artisan migrate --seed

npm install
npm run build                     # also generates resources/js/{actions,routes,wayfinder}
```

Two things worth knowing about that sequence:

- **`npm run build` is not optional on a fresh clone.** Wayfinder's generated route helpers live in `resources/js/actions`, `resources/js/routes` and `resources/js/wayfinder`, and all three are gitignored. Until you build (or run `npm run dev`, or `php artisan wayfinder:generate`), every `@/actions` and `@/routes` import is unresolved and TypeScript will not compile.
- **`.npmrc` sets `ignore-scripts=true`**, so npm lifecycle scripts do not run on install.

### About `composer setup`

There is a `composer setup` shortcut, but note what it does:

```
composer install → copy .env → key:generate → migrate --force → npm install → npm run build
```

**It does not seed.** Run it and you get an empty portal with flat, empty charts. If you use it, follow up with `php artisan db:seed`.

## 3. Environment reference

### Must set

| Variable | Notes |
|---|---|
| `APP_KEY` | Generated by `php artisan key:generate`. **See the warning below.** |
| `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT` | Defaults assume a local PostgreSQL with a `postgres`/`postgres` role. |
| `APP_NAME` | Ships as `Laravel`. It feeds `VITE_APP_NAME` and the desktop window title, so set it. |

> **Generate `APP_KEY` once, before seeding, and do not regenerate it.** The app key is also the HMAC key for result tamper-evidence (`app/Support/ResultIntegrity.php`). Changing it on a database that already holds results invalidates every stored result signature.

### Feature knobs

| Variable | Default | Effect |
|---|---|---|
| `RESULT_FAILURE_THRESHOLD` | `40` | Failure-rate percentage above which a course is flagged (README §7). This is only the fallback — once an admin sets the threshold in-app it is read from the `settings` table instead. |
| `OLLAMA_URL` / `OLLAMA_MODEL` | `http://localhost:11434` / `llama3.2` | Recommendation phrasing — see §7. |
| `DESKTOP_WEB_URL` | `http://localhost:8000` | Where the desktop shell points — see §6. |
| `NATIVEPHP_APP_ID`, `NATIVEPHP_APP_AUTHOR`, `NATIVEPHP_APP_VERSION` | | Desktop packaging metadata. |

### Fine as shipped in development

`MAIL_MAILER=log` (mail is written to the log, nothing is sent), and `CACHE_STORE` / `QUEUE_CONNECTION` / `SESSION_DRIVER` all on `database`.

### Unused unless you opt in

`AWS_*`, `REDIS_*`, `MEMCACHED_*`. None are read with the default drivers above.

### Read by the code but absent from `.env.example`

These are all optional — the defaults are what you get today — but they are not discoverable from `.env.example`:

| Variable | Default | Defined in |
|---|---|---|
| `LLM_DRIVER` | `ollama` | `config/llm.php` — set to `null` to disable the model entirely |
| `OLLAMA_TIMEOUT` | `8` | `config/llm.php` |
| `RESULT_CURRENT_SESSION` | `2025/2026` | `config/grading.php` |
| `DESKTOP_HEALTH_PATH` | `/up` | `config/desktop.php` |
| `DESKTOP_HEALTH_TIMEOUT` | `3` | `config/desktop.php` |
| `OCTANE_SERVER` | `roadrunner` | `config/octane.php` |

## 4. Database and demo data

### Why PostgreSQL specifically

The analytics are SQL, not PHP. The CGPA trend is a window function and the failure-rate report uses `COUNT(*) FILTER` (README §6 and §7). The application is deliberately not portable to another database engine.

The migrations *are* driver-guarded so they also run on SQLite — `jsonb` degrades to `json`, the partial indexes are skipped ([results](database/migrations/2026_02_01_000008_create_results_table.php), [result_audits](database/migrations/2026_02_01_000011_create_result_audits_table.php), [recommendations](database/migrations/2026_02_01_000012_create_recommendations_table.php), [course_lecturer](database/migrations/2026_02_01_000006_create_course_lecturer_table.php)). That exists only so NativePHP's SQLite-only bundled PHP binary can migrate its internal tables. **It is not a supported way to run the portal.**

### What the seeder gives you

[`database/seeders/DatabaseSeeder.php`](database/seeders/DatabaseSeeder.php) builds a simulated UNN dataset spanning sessions 2020/2021 through 2025/2026, so every chart has something real to plot. Deliberately included:

- `MTH 201` and `COS 302` seeded above the failure threshold, so the flagging feature visibly fires
- one student with a declining CGPA, so the recommendation layer has a genuine case to speak to

## 5. Running the app

```bash
composer dev
```

One command — it runs `php artisan dev`, which starts the PHP server, Vite, the queue worker and log tailing together. This is the recommended default.

Two-terminal alternative:

```bash
php artisan serve     # http://localhost:8000
npm run dev           # Vite
```

Then open `http://localhost:8000` and sign in with an account from §4.

### Confirming it works

- **`student@unn.edu.ng`** → dashboard shows the CGPA trend line chart and a recommendation
- **`lecturer@unn.edu.ng`** → an assigned course, score entry, grade distribution for that course
- **`examofficer@unn.edu.ng`** → submitted sheets to approve, then a separate publish action
- **`admin@unn.edu.ng`** → the failure-rate table with `MTH 201` and `COS 302` flagged

If the charts are empty, the seeder never ran — see §2.

## 6. Desktop shell (NativePHP)

### How it works

The desktop app is an Electron **shell over the running web app**, not a self-contained copy of it. NativePHP bundles a static PHP binary built without `pdo_pgsql`, so the desktop process cannot open the PostgreSQL database itself. Instead it loads `DESKTOP_WEB_URL` over HTTP ([`NativeAppServiceProvider`](app/Providers/NativeAppServiceProvider.php), [`PortalConnection`](app/Services/PortalConnection.php)) and gets exactly the same pages, database and session auth as the browser. There is no separate API — per README §2, there is no API at all.

**A web server must already be running before you start the desktop app.**

```bash
# .env
DESKTOP_WEB_URL=http://localhost:8000

php artisan native:run        # native:serve exists but is deprecated in NativePHP v2
```

Or with Vite running alongside it:

```bash
composer native:dev
```

### Offline behaviour

On boot the provider calls `PortalConnection::isReachable()`, a `GET` against `DESKTOP_HEALTH_PATH` (default `/up`) with a `DESKTOP_HEALTH_TIMEOUT` second timeout. If that fails, the window opens a local offline screen with a retry button instead of the portal.

That view ([`resources/views/desktop/offline.blade.php`](resources/views/desktop/offline.blade.php)) inlines its own CSS and uses no `@vite` and no external fonts, deliberately, so it renders with no server and no build. A test asserts this — don't add `@vite` to it.

### Packaging

```bash
php artisan native:build
```

`php artisan native:install` runs automatically on `composer update` via the `post-update-cmd` hook.

## 7. Optional: Ollama for recommendations

**This is optional. The recommendation feature works with no model and no internet** — an offline fallback is a hard requirement of the design (README §8), not a degraded mode.

```bash
# to enable LLM phrasing
ollama pull llama3.2          # must match OLLAMA_MODEL

# to skip the model entirely
LLM_DRIVER=null               # in .env
```

### How it degrades

[`RecommendationService`](app/Services/RecommendationService.php) runs SQL facts → PHP rules → LLM phrasing → cache in the `recommendations` table. If no driver is configured, or the Ollama call throws `LlmUnavailable` (timeout, non-2xx, empty response), it falls back to rule-based text and records `source = fallback` on the row, logging at info level. Nothing breaks and nothing blocks.

Only the computed facts and flags are ever sent to the model — never raw result rows.

## 8. Tests, lint and static analysis

### Create the test database first

```bash
createdb unnresultportal_test
```

> **[`phpunit.xml`](phpunit.xml) hardcodes its database connection and does not read `.env`.** It sets `DB_CONNECTION=pgsql`, `DB_DATABASE=unnresultportal_test`, host `127.0.0.1:5432`, username and password both `postgres`. If your local PostgreSQL uses different credentials, either create a matching `postgres` role or edit `phpunit.xml`. Without this database the entire suite fails on the first test.

### Running

```bash
composer test          # Pint (check) + PHPStan + the full test suite
composer ci:check      # everything above plus eslint, prettier and tsc — the CI gate
```

Individually:

```bash
php artisan test --compact
php artisan test --compact --filter=GradingTest

composer lint          # Pint, fixes in place
composer types:check   # PHPStan / Larastan, level 7
npm run lint:check     # eslint
npm run format:check   # prettier
npm run types:check    # tsc --noEmit  (build the frontend first — see §2)
```

PHPStan runs at **level 7** over `app/`, `bootstrap/app.php`, `config/`, `database/` and `routes/`.

### One test to know about

[`tests/Feature/DesktopSqliteMigrationTest.php`](tests/Feature/DesktopSqliteMigrationTest.php) runs the entire migration set against a throwaway SQLite file to prove nothing is PostgreSQL-only without a guard. If you add a migration using `jsonb`, a partial index, or any other pgsql-specific feature, wrap it in a driver check or that test will fail.

## 9. Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `tsc` cannot find module `@/actions/...` or `@/routes/...` | Wayfinder's generated output is gitignored. Run `npm run build`, `npm run dev`, or `php artisan wayfinder:generate` before typechecking. |
| `Unable to locate file in Vite manifest` | The frontend has not been built. `npm run build`, or run `npm run dev` / `composer dev`. |
| `could not find driver`, or a `PDOException` on the first query | `pdo_pgsql` is not installed or not enabled. Check `php -m \| grep pdo_pgsql`. |
| Tests fail with "database does not exist" or connection refused | `createdb unnresultportal_test`. Credentials come from `phpunit.xml`, not `.env` — see §8. |
| Charts and dashboards are empty | The seeder never ran. `php artisan db:seed`, or `php artisan migrate:fresh --seed`. Remember `composer setup` does not seed. |
| Desktop window shows the offline screen | Nothing is serving `DESKTOP_WEB_URL`. Start `php artisan serve` first and confirm `GET /up` responds. |
| `.env` change has no effect | `php artisan config:clear`. Under Octane, restart the workers — config is loaded once at boot. |
| Students can see unpublished results | They shouldn't — that is a documented invariant (README §9). Check `status = 'published'` filtering and open an issue. |

## 10. Known documentation discrepancies

README.md declares itself the authoritative spec, but the code has moved past it in three places. Recorded here so nobody reads the spec and concludes the code is wrong:

| README says | Reality |
|---|---|
| §2 — "PHP 8.2+" | `composer.json` requires `^8.3`; CI runs 8.5 |
| §10 — use `maatwebsite/excel` | The code uses `phpoffice/phpspreadsheet` directly ([`ExcelResultImporter`](app/Services/ExcelResultImporter.php)) |
| §4 — "7 tables", with `courses.lecturer_id` | 16 migrations. Also `settings`, `result_signatures`, `result_audits` and `recommendations`, and a `course_lecturer` pivot (teaching teams) rather than a single `lecturer_id` column |

**CI cannot currently pass as written.** [`.github/workflows/tests.yml`](.github/workflows/tests.yml) provisions no `services: postgres` block, so `composer setup`'s `migrate --force` and the PostgreSQL-backed test suite have no database to connect to on GitHub Actions.
